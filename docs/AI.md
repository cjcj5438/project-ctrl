# AI 助手

## 它是什么

项目级 AI 助手：它看得懂你的仓库，能写出可直接运行的服务配方、解释服务为什么起不来、
整理项目画像与 README——但**不能改你的任何文件**。

驱动的是你自己装在本机的 [`pi`](https://github.com/earendil-works/pi)（`@earendil-works/pi-coding-agent`）
编码代理，App 通过 `--mode rpc` 与它对话；模型、登录、计费都走 pi，App 不内置任何模型。

入口在项目详情右侧的 400px 抽屉（头部「AI 助手」按钮开合）；路径丢失的项目不提供抽屉。
侧栏的「AI 任务」区在有活跃会话时才出现，列出「项目名 · 任务」与状态点
（运行中 / 恢复中 / 等待确认），点一下跳到该项目的「服务」页签。

## 安装与前提

```sh
npm i -g @earendil-works/pi-coding-agent   # 需要 ≥ 1.1.0，App 会检查版本
```

1. **node**：pi 是 node 程序，PATH 上要有 node（App 的文案要求 ≥ 22.19；
   实际只确认「PATH 上能找到 node」，版本不够时由 pi 自己报错）。
2. **在 pi 里登录模型**：直接跑 `pi`，在 TUI 里 `/login`；或手工写
   `~/.pi/agent/models.json`（兼容端点与模型）与 `~/.pi/agent/auth.json`（凭据）。
   模型凭据属于 pi，App 只列出可用模型，不保存任何密钥。
3. **在 App 里指定怎么用**：「设置 → AI」里可以填 pi 可执行文件的绝对路径（留空按 PATH 查找）、
   选主模型与轻量模型、以及各自的思考档位（`off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`）。
   改完点「保存」后立刻生效；「刷新模型列表」会跳过 5 分钟缓存重新读 pi 的模型清单。

设置页顶部还显示解析到的 pi 路径、版本与「运行中会话」数。**pi 没装好时不会弹错误框**，
而是把原因写进设置页与抽屉底部——抽屉在 `problem` 存在时会用引导块替换输入框，直接给「打开设置」。

常见 `problem` 原文：

| 文本 | 含义 |
|---|---|
| `未找到 pi：请执行 npm i -g @earendil-works/pi-coding-agent，或在设置中填写 pi 路径` | PATH 上没有 pi，或设置里的路径无效 |
| `找不到 node：pi 需要 node ≥ 22.19` | PATH 上没有 node（pi 的 `--version` 也跑不起来） |
| `pi 版本过低（1.0.x），需要 ≥ 1.1.0：…` | 升级 pi |
| `pi 路径无效：/path（需要是绝对路径且可执行）` | 设置里填的不是绝对路径或没有执行权限 |
| `pi --version 超时` / `无法解析 pi 版本` | pi 卡住或输出不是常规版本号；多半是包坏了，重装 |

登录没配好时，pi 的报错以 `No model selected` / `No API key` / `Authentication failed` 开头，
抽屉里会出现「先配置 AI」卡片（带「打开设置」），而不是一条普通错误。

## 只读契约（重要）

AI **不能修改项目文件，不能执行 git 写操作，不能装包**。这不是提示词里的请求，而是三层硬约束：

1. **工具白名单**：启动 pi 时只开放 `read`、`grep`、`find`、`ls`、`bash` 与 8 个 `pc_*` 结构化工具。
   `edit` / `write` / 其它未知工具一律拒绝（返回「只读模式：AI 不能修改文件或执行该工具」）。
2. **bash 只读白名单**：命令先过词法检查，再逐条比对白名单；其余全拦。
3. **读路径限制**：`read` / `grep` / `find` / `ls` 的路径必须落在**项目目录内**（词法归一后还会解析软链接，
   项目内的软链接指向外面同样拦），且不能是密钥文件。

### bash 白名单的实际内容

先做三道前置检查：

- 命令里不得出现 shell 元字符：`;` `&` `|` `<` `>` `$` 反引号 `(` `)` `{` `}` `\` 以及换行——
  没有它们就拼不出管道、重定向、子命令；
- 程序名不能含 `/`（不能写 `/bin/ls`）；
- 任何参数以 `--output` 开头的一律拒绝。

然后按程序名判：

| 类别 | 允许的形态 |
|---|---|
| 版本查询 | `node` / `npm` / `pnpm` / `yarn` / `bun` / `deno` / `go` / `cargo` / `rustc` / `python` / `python3` / `pip` / `pip3` / `uv` / `java` / `mvn` / `gradle` / `ruby` / `php` / `docker` / `git` 加 `--version`、`-v`、`-V` 或 `version` |
| 依赖 / 包信息 | `npm` `pnpm` `yarn` `bun`：`outdated` / `ls` / `list` / `why` / `view` / `info`；`pip` `pip3`：`list`；`uv pip list`；`cargo tree`；`go list` / `go env` |
| 只读 git | `status` / `log` / `diff` / `show` / `rev-parse` / `ls-files` / `describe` / `blame` / `shortlog`；`branch` / `remote` 只允许 `-a` `-r` `-v` `-vv` `--list` `--show-current` `--verbose` `--all` |
| 只读 docker | `ps` / `images` / `version` / `info`；`compose ps` / `compose config` / `compose ls` |
| 端口查询 | `lsof -nP -iTCP -sTCP:LISTEN` 或 `lsof -nP -iTCP:<数字> -sTCP:LISTEN`（四个参数，顺序固定） |
| 杂项 | `which <名字>`（只能是两个词）、`uname -a`、`sw_vers`（不带参数） |

`bash` 的超时由闸门改写：默认 120 秒，写再多也封顶 120 秒。

被拦的不只是 `rm` / `git commit` / `git push`：`git fetch`、`git tag`、`git add`、`pnpm install`、
`npm run build`、`docker compose down`、`ls | head` 也都是拒绝的——**AI 不能改动仓库的任何状态**。

### 密钥文件不可读

即便在项目内，这些文件名也直接拒绝（理由里会说明「变量名可通过 `pc_project_context` 获取」）：

- `.env`、任何 `.env.*`；例外：`.env.example`、`.env.sample`、`.env.template`、`.env.dist`
- `.npmrc`、`.netrc`、`.pypirc`
- 扩展名为 `.pem` / `.key` / `.p12` 的文件
- 以 `id_rsa` 或 `id_ed25519` 开头的文件

`grep` 传 `glob` 时，glob 的最后一段同样按上述规则判（`--glob '**/*.pem'` 也被拦）。

## 五类任务

抽屉里五个快捷按钮各对应一个预设任务（也可以直接打字自由对话）。任务用哪个模型由设置决定：
配置 / 诊断 / README 用**主模型**，体检 / 画像用**轻量模型**。

| 任务 | 它做什么 | 产出卡片 | 卡片上的后续动作 |
|---|---|---|---|
| 配置服务 | 读清单、脚本、compose 文件，推断出能直接跑起来的完整配方 | 「服务配方（第 N 轮）」：写入层、前后 diff、会被写进配方的 env **变量名**、说明 | 「批准并验证」（可勾「先执行 install/build 步骤」）/「拒绝」（可写原因，AI 据此重做） |
| 诊断 | 针对某个异常服务读配方、状态、预检与最近 200 行日志，给根因与证据 | 「诊断 服务名」：归类（配置 / 代码 / 环境 / 外部依赖 / 原因不明）、现象、原因、证据、建议 | 配置问题：「应用并验证」（可勾「先执行步骤」）；任何问题：「重新验证」「继续诊断」；证据的文件:行号可点开 VS Code |
| 体检 | 只读巡检：清单、锁文件、env 示例、配置 | 「体检报告」：按 错误 / 警告 / 提示 分组，每条可带排查命令（可复制） | 「重新体检」 |
| 画像 | 生成一句话简介、技术栈、标签 | 「项目画像」：摘要 / 技术栈 / 标签，三段都可勾选 | 「采纳所选」/「忽略」 |
| 补全 README | 按真实脚本写一份完整 README | 「README 草稿」：前 12 行预览 | 「在编辑器中打开草稿」（切到 README 页签并进入编辑态，**不自动保存**）/「忽略」 |

「诊断」按钮在没有异常服务时置灰；有多个异常服务时变成下拉，逐个选。

卡片右上角是状态徽章：待确认 / 自动修正 / 验证中 / 待处理 / 已批准 / 已通过 / 失败 / 已拒绝 /
已超时 / 已回滚 / 已中止 / 已撤销 / 已忽略。

## 配置闭环

1. **AI 提交完整集合**。`pc_propose_services` 是**覆盖语义**：提交的集合就是最终结果，
   没提交的现有服务会被删除。App 会严格校验（服务名唯一、`depends_on` 只能指向本集合内、
   `ports.listen` 不为 0、路径不能出项目…），校验失败直接退回给 AI，不消耗尝试次数。
2. **你预览并批准**。卡片给出前后两份配方的 diff、将写入哪一层、以及配方里出现的 env 变量名。
   勾「先执行 install/build 步骤」会让 App 在启动前先跑一遍 `steps`；当配方里有步骤、且依赖目录确实缺了
   （有 `package.json` 没 `node_modules`、有 `pyproject.toml` 没 `.venv`、有 `composer.json` 没 `vendor`）时，
   这个开关默认就是勾上的。
3. **写入当前生效层**：项目里有 `.project-ctrl.json` 就写这个文件（整份覆盖）；否则只写本机数据库。
   写文件前先抓原文件的快照，用于回滚。
4. **启动 + 健康检查**：先停掉「旧集合 ∪ 新集合」里的活跃服务，再按 `depends_on` 拓扑顺序启动，
   等每个服务就绪，然后**再观察 3 秒**——要求仍在运行且没有偷偷重启过。
5. **失败自动回喂**：失败时把失败原因与该服务最近 150 行日志交回 AI，并要求它重新提交修正后的完整配方；
   这一轮**不再弹确认**，直接应用（卡片标「自动修正 · 第 N 轮」）。
6. **最多 3 轮**。第 3 轮仍失败：停掉本轮启动的服务、按快照回滚配方，验证卡变成「已回滚」，
   并给出「仍然采用最后一次配置」——点它就把最后一版配方写回生效层（不重启，也不验证）。

通过之后**服务保持运行**，验证卡上留着「停止服务」与「撤销配置」（撤销会先停掉本轮启动的服务，
再把配方还原到快照）。同一项目同一时刻只允许一个配置校验，第二次提交会被拒绝（避免两个会话互相覆盖）。

## 诊断闭环

- 归类为**配置问题**且带了 `config_fix` 时，卡片上有「应用并验证」：App 把修复**合并进**当前集合
  （同名覆盖、新服务追加），当作「已批准的第 1 次」跑上面那套启动 + 健康检查；失败时同样自动回喂，
  最多 3 轮。
- 归类为**代码问题**（或其它）时不动配置：只给证据（文件 + 行号 + 原文片段），点文件路径在 VS Code 里
  定位到那一行。
- 「重新验证」= 停掉该服务、重新启动、再判一次就绪；失败则把轮次 +1，卡片变「失败」，
  「继续诊断」把最新状态与最近 150 行日志交回 AI 再诊断一轮（最多 3 轮，用完按钮消失）。
- 验证通过后卡片进「已通过」，不再提供动作按钮。

## 会话与可靠性

- 一个项目一个会话，**不保留历史**：转录只在内存里，退出 App 后重新打开是空白对话（「新对话」也会立即丢弃当前上下文）。
- 崩溃自动恢复：pi 进程非主动退出时，60 秒窗口内最多自动恢复 **2 次**，
  且**复用同一个 session id**——pi 会从 `--session-dir` 里的会话文件续上下文，所以恢复后能接着说。
  超过 2 次就停在「异常」，并显示 stderr 尾部。
- 闲置 **15 分钟**自动休眠，释放进程；之后再发消息会重新拉起，上下文照样续上（表面上看不出差别）。
  某轮对话 5 分钟完全没有输出会被判定卡死并终止本轮。
- 同时最多 **6 个**会话进程；满了会先把最久没动静的空闲会话睡掉，仍不够则拒绝新会话。
- 模型调用失败时，重试期间转录里只看得到「模型调用失败，正在重试（n/m）」；**回合结束
  （正常收尾 / 主动中止 / 进程崩溃）时才落一条最终的 `error` 提示**（`模型调用失败：…` 或
  `重试失败：…`），每轮最多一条。之所以攒到最后，是因为 pi 的 `message_end{error}` 先于
  `auto_retry_start` 到达，当场报会把「正在重试（3/3）」顶成用户看到的最后一行。
  认证 / 选型类失败（`No model selected`、`No API key`、`Authentication failed`）例外：
  不等回合结束，直接给「先配置 AI」卡片。失败回合的助手气泡显示「（本轮没有返回内容）」而不是空白。
- 退出 App：先让进行中的配置校验回滚，再关 stdin（pi 收到 EOF 自行收尾）、`SIGTERM`、必要时 `SIGKILL`，
  最后清掉临时会话文件与孤儿进程记录。被 `kill -9` 留下的 pi 进程会在下次启动时回收，
  但要三道校验全过：pid 仍存活、`ps` 的 `lstart` 与本机记录逐字相同、进程组号（pgid）也对得上
  ——同 pid 同启动时间的陌生进程一样不动。命令行只做「像不像我们的 pi」的可行性判断：
  pi 会把 `process.title` 改成 `pi`，命令行缩成 `pi` 甚至只剩 `pi --flag`，所以不再要求出现
  `--mode rpc` / `pc-extension`，而是接受 `pi`、`pi …`、`pi-coding-agent`、`pc-extension`、
  `--mode rpc`、`node …`、`cli.js`；argv[0] 提到 `project-ctrl`（本 App 自己的二进制）、或以
  shell 开头的一律排除。判不过就只打一行 `跳过回收 …`，故意留着不杀——宁可漏收一个孤儿，
  也不误杀用户自己的进程。

## 数据与隐私

**AI 能看到什么**：项目上下文由 App 组装后随任务一起给出，内容包括路径、`.project-ctrl.json` 状态、
服务声明、探测到的技术栈 / 候选脚本 / compose 栈 / Makefile 目标、工具链版本、git 概况、
以及 `env` 文件的**键名**（`files` / `examples` / 缺失的键）——**从不出值**。
载荷总量封顶 24 KB，超限时按「候选 → 工具链 → 端口 → env 列表」的顺序裁剪，`services` 永不裁剪。
其余细节（比如某个 `package.json` 里写了什么）由 AI 自己用只读工具去读。

**`~/.project-ctrl/ai/` 下有什么**：

```
settings.json      # pi 路径、主/轻量模型与思考档位（不含任何密钥）
pc-extension.ts    # 内嵌的 pi 扩展（8 个 pc_* 工具），内容变化时重写
system.md          # 内嵌的系统提示词（助手约定 + 配方硬规则 + 覆盖语义说明）
sessions/          # pi 的临时会话文件，退出 App 时清空，可随时手工删除
```

**环境**：pi 子进程用 `env_clear()` 起，不继承你的 shell 环境（`.zshrc` 里的东西不会进去）。
只额外透传模型凭据类变量：

- 任何以 `_API_KEY` 结尾的变量；
- `ANTHROPIC_*`、`AWS_*`、`AZURE_OPENAI_*`、`CLOUDFLARE_*` 前缀；
- `PI_CODING_AGENT_DIR`。

并固定设置 `PI_TELEMETRY=0`（关掉 pi 自己的遥测）与 `PC_AI_SESSION`（会话 id）。
pi 的会话上下文会发给**你自己配置的模型服务商**——这是使用 AI 的固有前提，App 不介入。

## 批量画像

列表页头部的「AI 批量画像」：勾选项目（默认勾选还没有画像的，路径丢失的项目不出现）→「开始」。
每个项目起一个短命的 pi（`--no-session`，跑完即退），**并发 2**，单项目 5 分钟硬超时。
结果逐条显示：简介、技术栈、标签，可以单条「采纳」/「忽略」，也可以「全部采纳」；
任务进行中可「取消任务」。采纳只写本机数据库（简介、技术栈、标签），不碰仓库文件。

## 排查

- **设置页显示 `未找到 pi`**：`npm i -g @earendil-works/pi-coding-agent`，或把绝对路径填进设置。
  用 nvm / fnm 装的 node 常常不在 GUI App 的 PATH 上——填绝对路径最省事。
- **`找不到 node`**：同上，多半是 PATH 问题而非真的没装。
- **`pi 版本过低`**：升级到 ≥ 1.1.0 后回设置点「保存」或「检测」（结果缓存 60 秒）。
- **卡片提示 `No model selected` / `No API key`**：模型没在 pi 里登录。终端跑 `pi` → `/login`，
  或补 `~/.pi/agent/models.json` + `auth.json`。
- **AI 说某个文件读不了**：`.env*`、`*.pem`、`*.key`、`*.p12`、`id_rsa*`、`id_ed25519*`、`.npmrc`
  这些是故意拦的；要变量名让它用 `pc_project_context`。
- **会话卡在「恢复中」**：60 秒内崩了 3 次就会停下——看卡片上的 stderr 尾部，修好 pi 再发消息。
- **磁盘上 `~/.project-ctrl/ai/sessions` 越来越大 / 想清干净**：直接删，这是临时文件；
  App 启动与退出时也会清空。
- **想彻底重置 AI 设置**：删掉 `~/.project-ctrl/ai/settings.json`，下次启动按默认值（PATH 找 pi、
  跟随 pi 的默认模型）。
